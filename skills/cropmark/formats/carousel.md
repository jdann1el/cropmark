# Format: carousel (4:5, 1080x1350 per slide)

Technical dimensions/safe zones apply; layout, word-count and style patterns below are suggestions. The content contract and faithful reference take precedence over aesthetic prescriptions. Typography-only work is valid when it serves the brief.
LinkedIn: export as PDF. Instagram: same ratio on every slide. 4-10 slides (default 5-7). Per slide: headline ≤8 words, body ≤25 words. Feed test 360 px + a contact sheet of the whole set.

## Core idea
- The carousel is a **visual argument**, not the article pasted onto slides. Each slide answers: what should the viewer get in one glance, what evidence supports it, which words are big, what moves to the caption.
- Images carry hooks, comparisons, checklists, sharp takeaways. Nuance goes in the post caption.

## Structure
- **Slide 1, cover hook**: one concrete claim + one strong visual. Title 1-2 lines. Optional bottom strip of 3-5 key points or "what's inside". No long subtitle. Must work as a standalone single post.
- **Slides 2..N-1**: one idea per slide. Vary the slide role (see below); never repeat the same title+card layout across the set.
- **Rhythm**: dense, dense, breath. Insert a light slide (single statement / divider / big number) after 2-3 dense ones; after any full-bleed photo slide, the next slide must be text/data (never two full-bleed photo slides in a row).
- **Last slide**: closure in the voice of the set (takeaway list, "remember these 3", a closing question) + one real CTA (follow, save, link) only if the user has one. Cover and last slide must look distinct from body slides but share the system.
- Length: follow the brief; if unspecified, 5-9 slides; ~600-1000 words of source ≈ 5-7 slides, 1000-1800 ≈ 7-9, longer → cap at 8-10 and push the rest to the caption. Merge slides when lower areas go empty.

## Slide roles (pick varied ones)
Hook · problem scene · myth vs reality · checklist · comparison · proof screenshot · big quote · steps · buy list · recap.

## Layout recipes (short named patterns)
- **Issue Cover**: top meta row, 2-4 line title, image well 35-55% of height, bottom points strip.
- **Photo-Led Cover**: photo owns the canvas, small restrained title in its quiet zone (needs a photo with a ≥30% calm band; else use Issue Cover).
- **Accent Cover**: flat accent or off-white field, very large light title, one simple diagram block, meta strip.
- **Field Note**: big documentary photo + narrow caption column + one large takeaway.
- **Essay Split**: title/quote left, 2-3 short paragraphs right, hairline between. Needs ≥3 short paragraphs or it becomes Pull Quote.
- **Pull Quote / Thesis**: one sentence huge; the only recipe allowed ≤60% fill, but needs anchors: top kicker, hairline + source row near bottom.
- **Tall Ledger / Checklist**: 4-6 full-width rows, each 118-170 px tall, index column + item + consequence. Short lists never sit in the middle third only.
- **Evidence Wall**: 2x2 or 3-col grid of screenshots, short captions, one anchoring headline. Only if images read at final size.
- **Vertical Pipeline**: 3-5 numbered steps stacked, hairline between. 6+ steps → split slides.
- **Before / After (stacked)**: top block dimmed (~0.65 opacity), bottom block full; never left-right on a portrait canvas.
- **KPI Tower / H-Bars**: 3-4 big numbers, or 5-10 ranked bars; >8 grid cells → bars.
- **Matrix + Hero Stat**: 4-6 cells + one bottom-line number.
- **Hero Question**: closing question fills the slide, kicker top, prompt + meta bottom.
- **Screenshot Stage**: UI shot contain-fit on a quiet stage, 55-70% of canvas, straight, no tilt; crop to the real subject first.

## Two style stances (pick one per set, never mix)
- **Editorial**: serif display, quiet text, paper + ink palette, subtle texture/grain, ledger rows, pull quotes, big photo wells. Feels slow, considered.
- **Swiss**: grotesk sans, strict left-aligned grid, hairlines, flat fills, exactly one saturated accent, no shadows/gradients/rounded cards. Feels engineered, quantified.
- Choose by intent ("feature story" vs "release note"), not by topic. One palette per set: ink + paper + 1 accent (+ soft accent tint).

## Typography & spacing scale (1080 px wide)
- Display/cover title 96-140 px (Latin can go to 160-200 if 1-3 words); slide title 64-96 px, ≤2 lines, ≤ ~18 characters/line Latin; mid title 48-56; lead 30-34; body 28-32; kicker/meta 20-24 uppercase mono or sans with +0.15-0.22em tracking.
- Line-height: titles 0.95-1.15, body 1.35-1.5. Hard-break titles at meaning seams; never let auto-wrap choose.
- Spacing on an 8-px base: 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 96. Outer padding 80-96 px. Title → next block ≥28 px; local heading → content ≥16 px.
- Footer/page meta pinned by flex (`margin-top:auto`) in a column layout, never absolutely positioned over growing content.
- Overflow ladder: measure first. 1-40 px → tighten one gap; 40-90 → compact local spacing; 90-160 → trim title size slightly or one paragraph; 160+ → change recipe or cut content. Then re-check for a new empty bottom band.

## Continuity devices
- Same grid, margins, palette, type pair on every slide.
- Page counter `03 / 08`, recurring category row, one issue element per slide (top OR bottom strip, not both).
- Swipe cue on the cover (arrow/"swipe") and a mirrored visual motif on the last slide.
- Optional cross-slide bleed element (test how the platform shows slide edges).
- Numbered sections echo the cover's promise ("5 mistakes" → slides labelled 1/5..5/5).

## Content planning
1. Core claim in one sentence. 2. Viewer promise (why swipe). 3. Section map, 4-8 ideas. 4. Slide hooks: plain, concrete, verbs + consequences ("High-tops trap heat" beats "Shoe choice"). 5. Body fragments: only words the visual needs.
- Lead product posts with the user-facing change, then the feature name; AI/tool posts with the workflow change.
- Plan per slide: `NN / role / headline / body / visual evidence / recipe`. Show the plan for approval when the user wants a gate.
- Visible copy describes the viewer's scene, never production terms ("information budget", "layout").
- Never invent data, quotes, release details or percentages. Ask for screenshots/photos for news, tutorial, data and review posts: real artifacts beat filler.

## Hook copy (cover)
- Two-line hook: line 1 ≤40 chars, unexpected/specific, not a question; line 2 ≤40 chars, contradicts or reframes. Prefer digits.
- Angles: number-led, contrarian, before→after, authority/tool name, admission, future shock. "I/How I" only for real author experience.

## Title shortening (square covers, cross-posting)
- Each surface gets its own sentence: tall cover title > wide cover title > square title (shortest).
- 5 steps: find the core verb → find its object → compress to ~2-5 words → drop secondary language/brand words unless they carry the verb → add a tiny subtitle only to disambiguate.
- Patterns: Verb+Object (one line) · Two-clause cut at the comma (two short lines) · Single Big Word + small meta line · Number-led ("-3.4 kg / lighter pack").
- Don'ts: squeezing the long title in, "How to / Why" preambles, 3-line titles (shorten instead), long subtitles.

## Portfolio-level additions
- **Seamless panorama**: design all slides as one wide canvas (N×1080 wide) and slice; cutout photos and shapes cross slide borders so every slide "pulls" to the next. Keep each slide readable on its own.
- **Chapters**: problem → cause → solution → proof → CTA; the cover states the promise, slide headers echo it ("1/4").
- **Interior slides are never "text on an empty colour"**: each needs one visual anchor (cutout, icon-scale illustration, photo strip, giant numeral, brand shape) occupying ≥25% of the slide.
- Closing slide: person/brand photo + one real CTA ("guarda este post", follow) in the set's voice.
